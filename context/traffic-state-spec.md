# Traffic State Spec — flow, density, speed

Reference for what a `VTransport` measures, in what units, and the identity that
ties the three together. Written against the current code on this branch
(Pathway owns the lane DLL, VTransport owns the per-segment `vdeque`).

Sources: May, *Traffic Flow Fundamentals*, ch. 2; Treiber & Kesting,
*Traffic Flow Dynamics*, ch. 3.

---

## 1. The three quantities

A `VTransport` is **one lane × one road section**. Every quantity below is
therefore **per lane**. Multiply by the lane count for a cross-section total.

| Symbol | Name | Definition | Unit |
|--------|------|------------|------|
| `k` | density | vehicles on the section at an instant ÷ section length | veh/km/lane |
| `v` | space-mean speed | arithmetic mean of the speeds of the vehicles on the section at that instant | m/s |
| `q` | flow | vehicles crossing a fixed point ÷ observation interval | veh/h/lane |

### Density `k`

    k = n / L

`n` is the instantaneous occupancy of the section — `vdeque.size`. `L` is the
section length. This is a *spatial* measurement: it needs the whole section at
one moment, which is exactly what the deque holds.

### Space-mean speed `v`

    v = (1/n) · Σ vᵢ        over the n vehicles on the section at that instant

The arithmetic mean is correct **because the sample is spatial**. Averaging the
speeds of the cars that happen to be on a section at one instant *is* the
space-mean speed by definition.

Do not confuse this with **time-mean speed**, the mean of spot speeds recorded
at a detector over an interval. The two are not equal:

    v_t  ≥  v_s          (Wardrop)

and only `v_s` satisfies the identity in §2. If space-mean speed ever has to be
recovered from point measurements, it is the *harmonic* mean of the spot speeds:

    v_s = n / Σ (1/vᵢ)

Stopped vehicles (`v = 0`) belong in the average. They are why `v_s` drops in a
jam, and dropping them would break §2.

### Flow `q`

    q = N / T

`N` is the number of vehicles crossing a fixed cross-section during `T`. This is
a *temporal* measurement at a point, not a property of a section, and it must be
counted over a bounded window — a cumulative mean since the start of the run
cannot show a breakdown or a recovery.

Vehicles **generated by a source** are not flow. That is demand. Under
congestion demand exceeds discharge, so reporting arrivals as throughput reads
high exactly when the difference matters.

## 2. The identity

    q = k · v_s

with consistent units. Working in veh/km, m/s, veh/h:

    q [veh/h/lane] = k [veh/km/lane] · v_s [m/s] · 3.6

This is the fundamental relation of traffic flow. It holds by definition when
`v_s` is the space-mean speed, and fails when a time-mean speed is substituted.

## 3. Where each is computed today, and what is wrong

### `VTransport.snapshotDensity` — wrong unit

    if length > 0.0 then vdeque.size.toDouble / length else 0.0

`length` is metres, so this returns **veh/m**. `Junction.jump` records it into
`recordDensity`. The HUD computes veh/km. Two densities, two units, one name —
anything comparing them is off by 1000.

### `Model.pushHudStats` — density

    val nVeh  = vt.vdeque.size
    val lenKm = vt.length / 1000.0
    densities(i) = if lenKm > 0.0 then nVeh.toDouble / lenKm else 0.0

Correct: veh/km per lane. The HUD panel labels it "Segment Density (veh/km)",
which omits *per lane*. The jam-density colour ramp (~150 veh/km) is right for a
single lane, so the number and the scale already agree — only the label is wrong.

### `Model.pushHudStats` — speed

    for v <- vt.vdeque do sumVelocity += v.velocity
    val avgSpeed = if totalVehicles > 0 then sumVelocity / totalVehicles else 0.0

Correct. This is the space-mean speed, aggregated over every lane-segment in the
model. The HUD calls it "Avg Speed"; it should say space-mean speed.

Note this excludes vehicles on `Ramp` and `FFConnector`, because
`pushHudStats` only matches `Pathway` and `VTransport` in `parts`. Defensible as
a mainline statistic, but it should be a stated choice rather than a side effect
of the match.

### `Model.pushHudStats` — flow

    val throughput = if elapsed > 0.0 then numActors / (elapsed / 3600.0) else 0.0

Wrong quantity, two ways:

1. `numActors` counts vehicles **created** (`Source.scala`, `VSource`). `Sink.leave`
   counts nothing. So this is cumulative demand, not throughput.
2. It is a cumulative mean over the whole run, not a windowed count.

It is also a network total while the density panel beside it is per lane.

## 4. What the code should provide

Owned by `VTransport`, so that the fire model and counter-flow read one place:

- `density: Double` — veh/km per lane. One definition, one unit, replacing the
  veh/m variant.
- `spaceMeanSpeed: Double` — m/s; arithmetic mean over `vdeque`; `0.0` when empty.
- `flow: Double` — veh/h per lane, from `density * spaceMeanSpeed * 3.6`.

The HUD's "Throughput" then comes from these, not from `numActors`.

A second, independently measured flow — counted from the crossings that
`Junction.jump` already records — is worth having later, but it is not needed to
make the basics correct.

---

## 5. Naming

Say which quantity is meant, every time. "Average speed" and "density" without a
qualifier are the two places this codebase has already drifted.

- speed → **space-mean speed** (`v_s`)
- density → **veh/km/lane**
- flow from `k·v` → **modelled flow**
- flow from crossings → **measured flow**
